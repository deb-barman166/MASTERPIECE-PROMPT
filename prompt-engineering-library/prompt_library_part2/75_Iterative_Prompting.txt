75. ITERATIVE PROMPTING
=====================================================================
Part of: The Ultimate Prompt Engineering Library (Part 2: Meta/

-----------------------------
1. TITLE
-----------------------------
Iterative Prompting — Refining Results Through Successive Conversation 
Turns

-----------------------------
2. DEFINITION
-----------------------------
Iterative prompting is the general practice of treating a task as a 
MULTI-TURN CONVERSATION — reviewing each response, providing specific 
feedback, and requesting adjustments across several successive turns — 
rather than expecting a single "perfect" prompt to produce the ideal 
result in one shot. This is the broad, everyday, HUMAN-DRIVEN 
counterpart to more formalized techniques like Self-Refine (file 21, 
where the MODEL manages its own multi-round improvement loop 
internally) — Iterative Prompting specifically describes the natural, 
conversational back-and-forth where a PERSON reviews output and steers 
subsequent turns, which is simply how most real-world prompting 
actually happens in practice.

Think of it like the difference between an art director giving one 
perfect, exhaustive brief and expecting a finished masterpiece on the 
first try (rarely how creative work actually happens) versus the more 
realistic, natural process of reviewing a first draft, giving specific 
feedback ("make the color warmer, move this element left"), reviewing 
the revision, giving more feedback, and converging on a great result 
through this natural conversational refinement process.

-----------------------------
3. PURPOSE
-----------------------------
Iterative prompting exists to:
- Reflect how PEOPLE ACTUALLY WORK with AI models in practice — most 
  real, effective use involves conversation and refinement, not a 
  single flawless prompt.
- Allow for DISCOVERY during the process — sometimes you don't know 
  exactly what you want until you see a first attempt and can react to 
  it specifically ("not quite that, more like...").
- Reduce the PRESSURE of getting the initial prompt perfectly right, 
  since refinement through conversation is a legitimate, expected, and 
  often more efficient path to a good result than exhaustive upfront 
  prompt engineering.
- Support COMPLEX, evolving creative or analytical work where 
  requirements naturally become clearer as the work progresses.
- Serve as the practical, everyday complement to all the more 
  structured techniques in this library — even a perfectly-crafted 
  prompt using every relevant technique often still benefits from a 
  round or two of conversational refinement.

-----------------------------
4. WHEN TO USE AND BEST MODEL OR LLM
-----------------------------
WHEN TO USE:
- Virtually ANY interactive chat-based task — this is less a special 
  technique reserved for specific situations and more the DEFAULT mode 
  of effective, natural AI interaction.
- Creative or exploratory work where you're discovering exactly what 
  you want as you see attempts and react to them.
- Situations where getting immediate feedback and making a specific, 
  targeted adjustment is faster/easier than trying to anticipate and 
  specify everything in a single perfect upfront prompt.
- Complex tasks that naturally benefit from your ongoing input and 
  course-correction as the work develops.

WHEN NOT TO USE:
- Programmatic/automated systems with no human in the loop to provide 
  iterative feedback (in this case, invest more upfront in prompt 
  design/testing since true iteration isn't available at runtime).
- High-volume, repetitive tasks where a well-optimized single-shot 
  prompt/template (via Prompt Optimization, file 70) is more efficient 
  than manual iteration on every single instance.
- Situations where you already know exactly what you want and can 
  specify it completely and precisely in one prompt — iteration for its 
  own sake when not needed just adds unnecessary turns.

BEST MODELS FOR ITERATIVE PROMPTING:
- ALL modern conversational LLMs are designed for and excel at 
  iterative, multi-turn interaction — Claude, GPT-4o/4.1/5-class, 
  Gemini, Grok, and others all maintain conversation context and respond 
  well to specific, targeted feedback across turns.
- Claude and GPT-4-class models are particularly good at maintaining 
  consistency with EARLIER established context/preferences across a 
  long iterative conversation, rather than "forgetting" prior feedback 
  in later turns.
- For CREATIVE iterative work (writing, code, design), models with 
  strong instruction-following and good memory of established stylistic 
  choices across the conversation tend to produce smoother iterative 
  refinement experiences.

-----------------------------
5. PROMPT FORMULA
-----------------------------
    [INITIAL PROMPT] → [REVIEW OUTPUT] → "This is good, but 
    [SPECIFIC FEEDBACK]. Please adjust [SPECIFIC ASPECT]." → [REVIEW 
    REVISED OUTPUT] → [FURTHER SPECIFIC FEEDBACK IF NEEDED] → [FINAL 
    RESULT]

-----------------------------
6. PROMPT STRUCTURE
-----------------------------
    1. Initial Prompt — a reasonable first attempt, not necessarily 
       perfect or exhaustive.
    2. Review — actually reading/evaluating the output against what you 
       actually wanted.
    3. Specific Feedback — targeted, concrete feedback about what to 
       change, referencing SPECIFIC aspects of the output rather than a 
       vague "make it better."
    4. Revision Request — a clear instruction incorporating that 
       specific feedback.
    5. Repeat as Needed — continue the review-feedback-revision cycle 
       until satisfied.
    6. Final Confirmation — explicitly confirming when the result meets 
       your needs, or ending the conversation naturally once satisfied.

Example skeleton:
    "[INITIAL REQUEST] 
    
    [Review the response] 
    
    'This is a good start, but [SPECIFIC THING TO CHANGE]. Can you 
    [SPECIFIC ADJUSTMENT]?' 
    
    [Review the revision] 
    
    '[FURTHER SPECIFIC FEEDBACK IF NEEDED, OR CONFIRMATION THAT IT'S 
    NOW RIGHT]'"

-----------------------------
7. BEST PRACTICES
-----------------------------
- Give SPECIFIC, TARGETED feedback rather than vague dissatisfaction — 
  "make the tone warmer" or "the third paragraph doesn't flow well, can 
  you tighten it" is far more actionable than "this isn't quite right."
- Don't feel obligated to get everything perfect in the FIRST prompt — 
  a reasonable starting attempt followed by targeted refinement is 
  often more efficient than exhaustively anticipating every requirement 
  upfront.
- Reference SPECIFIC parts of the previous output when giving feedback 
  ("the second bullet point" or "the opening line") rather than forcing 
  the model to guess which part of a longer response you're referring 
  to.
- Build on established context across turns — don't repeat the entire 
  original request from scratch each time; trust the conversation's 
  memory and just provide the incremental adjustment needed.
- Know when to STOP iterating — recognize diminishing returns, similar 
  to Prompt Optimization and Self-Refine, when further rounds aren't 
  meaningfully improving the result relative to the effort of continued 
  iteration.
- For genuinely important or high-value final outputs, consider a final 
  explicit confirmation step ("this looks perfect, thank you") which 
  also signals to the conversation that you're satisfied, rather than 
  leaving ambiguity about whether more iteration is expected.
- If you find yourself iterating extensively on the SAME TYPE of task 
  repeatedly across different sessions, consider whether the lessons 
  learned should be captured into a Template Prompting (file 43) or 
  Prompt Optimization (file 70) process to avoid re-deriving the same 
  refinements every time.

-----------------------------
8. COMMON MISTAKES
-----------------------------
- MISTAKE: Giving vague, non-specific feedback ("this isn't quite 
  right") that doesn't give the model clear direction on what 
  specifically to change.
  FIX: Provide specific, targeted feedback referencing exact aspects to 
  adjust.

- MISTAKE: Trying to craft one exhaustive, "perfect" initial prompt when 
  a reasonable starting attempt followed by natural refinement would be 
  more efficient.
  FIX: Feel free to start with a reasonable attempt and refine through 
  natural conversation rather than over-engineering the first prompt.

- MISTAKE: Re-explaining the entire original request from scratch at 
  each iteration instead of building incrementally on established 
  context.
  FIX: Trust the conversation's memory and provide only the incremental 
  feedback/adjustment needed.

- MISTAKE: Not recognizing when further iteration has diminishing 
  returns, continuing to refine well past the point of meaningful 
  improvement.
  FIX: Recognize when a result is good enough and conclude the 
  iteration process.

- MISTAKE: Repeatedly re-deriving the same refinements across separate 
  sessions for the same recurring task type, without ever formalizing 
  the learned improvements.
  FIX: Consider capturing recurring iterative learnings into a reusable 
  template or optimized prompt.

-----------------------------
9. EXAMPLES (BASIC, INTERMEDIATE, ADVANCED)
-----------------------------

--- BASIC EXAMPLE ---
Turn 1: "Write a short tagline for a coffee shop."
Response 1: "Great coffee, every time."
Turn 2: "This is a good start, but it's a bit generic. Can you make it 
more specific to the experience of a cozy, community-focused 
neighborhood coffee shop?"
Response 2: "Where neighbors become friends, one cup at a time."

Expected Output:
The second response demonstrates genuine responsiveness to specific 
feedback (moving from generic to community-focused), showing the 
natural value of iteration over trying to specify "cozy, community-
focused neighborhood coffee shop" in an exhaustive first prompt.

--- INTERMEDIATE EXAMPLE ---
Turn 1: "Write a Python function to validate email addresses."
Response 1: [a working function using a basic regex pattern]
Turn 2: "This works well, but can you also handle the edge case of 
emails with a '+' character (like 'user+tag@domain.com'), which are 
valid but might not match your current pattern?"
Response 2: [an updated function correctly handling the '+' character 
case]
Turn 3: "Perfect, this looks good now. Can you also add a docstring 
explaining the validation rules being applied?"
Response 3: [the final function with an added, clear docstring]

Expected Output:
A progressively refined function through 3 natural turns, each turn 
addressing a specific, concrete piece of feedback, arriving at a final 
result that's more complete and robust than what might have emerged 
from a single, exhaustive initial prompt trying to anticipate every 
requirement (edge cases, documentation) upfront.

--- ADVANCED EXAMPLE ---
Turn 1: "Help me design a database schema for tracking a multi-agent 
system's memory across 7 layers (working, episodic, semantic, 
procedural, emotional, social, meta-memory)."
Response 1: [an initial schema proposal with 7 separate tables]
Turn 2: "This is a reasonable starting structure, but I'm realizing 
episodic and semantic memory actually need to reference each other 
frequently (an episodic event often relates to semantic facts). Can 
you redesign with this cross-referencing need in mind, rather than 
treating all 7 as fully independent tables?"
Response 2: [a revised schema introducing a linking/junction table or 
foreign key relationships between episodic and semantic tables]
Turn 3: "Good, that's better. Now I'm concerned about query 
performance at scale — with potentially millions of episodic memory 
entries across 50+ agents, what indexing strategy would you recommend 
for the episodic table specifically, given it will be queried both by 
agent_id and by approximate time range frequently?"
Response 3: [specific indexing recommendations, e.g., a composite index 
on (agent_id, timestamp), addressing the exact stated query patterns]
Turn 4: "That addresses my performance concern. One more thing — can 
you add a brief comment to each table explaining its specific purpose, 
since I'll be sharing this schema with a collaborator who's new to the 
project?"
Response 4: [the final schema with clear, purpose-explaining comments 
added to each table]

Expected Output:
A genuinely sophisticated final schema design that emerged through 4 
natural iterative turns, each surfacing a specific consideration 
(cross-referencing needs, query performance at realistic scale, 
documentation for a collaborator) that likely wouldn't have all been 
anticipated in a single initial prompt — demonstrating how complex, 
evolving technical work naturally and effectively benefits from genuine 
iterative refinement rather than attempting exhaustive upfront 
specification.

-----------------------------
10. REUSABLE PROMPT TEMPLATE (as a practice, not a single prompt)
-----------------------------
    Turn 1: [Your initial, reasonable request — doesn't need to be 
    exhaustive]
    
    [Review the response against what you actually want]
    
    Turn 2: "This is good, but [SPECIFIC, TARGETED FEEDBACK 
    referencing exact aspects to change]. Can you [SPECIFIC 
    ADJUSTMENT]?"
    
    [Review the revision]
    
    Turn 3 (if needed): "[FURTHER SPECIFIC FEEDBACK, or explicit 
    confirmation: 'This is exactly right, thank you.']"
    
    [Continue iterating with specific, targeted feedback until 
    satisfied, recognizing when further rounds show diminishing 
    returns]
