=====================================================================
15. GRAPH-OF-THOUGHTS (GOT) PROMPTING
=====================================================================
Part of: The Ultimate Prompt Engineering Library (Part 1: Reasoning)
Author: Deb Barman
=====================================================================

-----------------------------
1. TITLE
-----------------------------
Graph-of-Thoughts Prompting — Reasoning as an Interconnected Network

-----------------------------
2. DEFINITION
-----------------------------
Graph-of-Thoughts (GoT) prompting is an advanced reasoning technique 
that generalizes Tree-of-Thoughts by allowing reasoning "thoughts" to 
be organized as a GRAPH rather than a strict tree — meaning thoughts 
can be MERGED, COMBINED, or REFERENCED from multiple other thoughts, 
not just branch linearly downward from a single parent. In a tree, 
each thought has exactly one parent; in a graph, a thought can draw on 
and synthesize INSIGHTS FROM MULTIPLE PREVIOUS THOUGHTS 
simultaneously, and reasoning can loop back to refine earlier nodes.

Think of it like the difference between a family tree (strict 
hierarchy, ToT) and a real research collaboration network, where 
Idea D might combine insights from Idea A AND Idea B together, Idea E 
might refine Idea A after seeing what worked in Idea C, and so on — 
a flexible web of interconnected, mutually-informing ideas rather 
than a strict branching hierarchy.

-----------------------------
3. PURPOSE
-----------------------------
Graph-of-Thoughts prompting exists to:
- Enable SYNTHESIS — combining the best parts of multiple different 
  reasoning branches into a single superior solution, which Tree-of-
  Thoughts cannot do (ToT can only pick ONE branch, not merge several).
- Handle genuinely complex problems where the best solution comes from 
  COMBINING insights (e.g., "Approach A's efficiency + Approach B's 
  accuracy = the ideal hybrid solution").
- Allow REFINEMENT LOOPS — going back to improve an earlier idea based 
  on what was learned from a later one, rather than only moving 
  forward or backtracking to abandon.
- Model complex, real-world problem-solving more accurately, since 
  human experts often synthesize multiple perspectives rather than 
  picking a single "winning" idea.
- Push reasoning quality further than ToT on the hardest, most 
  interconnected problems (research synthesis, complex system design, 
  strategic planning with many interacting factors).

-----------------------------
4. WHEN TO USE AND BEST MODEL OR LLM
-----------------------------
WHEN TO USE:
- Highly complex problems where the ideal solution likely COMBINES 
  elements from multiple different approaches, rather than picking 
  just one.
- Research synthesis tasks — combining findings/arguments from 
  multiple sources or perspectives into a coherent, superior 
  conclusion.
- Complex system design problems where different subsystems/
  considerations interact and inform each other (e.g., combining 
  security considerations with performance considerations with cost 
  considerations into one coherent architecture).
- Strategic business or technical decisions with many interacting 
  factors that can't be cleanly separated into independent branches.
- Advanced creative work where blending multiple distinct creative 
  directions produces a better result than any single direction 
  alone.

WHEN NOT TO USE:
- Simpler problems where Chain-of-Thought or Tree-of-Thoughts already 
  suffices — GoT is the most complex and expensive of these 
  techniques, reserved for genuinely hard problems.
- Problems where the different approaches are truly MUTUALLY 
  EXCLUSIVE and cannot be meaningfully combined (in this case, ToT's 
  "pick the best branch" approach is more appropriate).
- Time/cost-sensitive applications, since GoT typically requires the 
  most tokens, turns, and computational overhead of any prompting 
  technique in this reasoning family.
- Simple factual or single-step tasks.

BEST MODELS FOR GRAPH-OF-THOUGHTS:
- GPT-4o/4.1/5-class and Claude (Opus/Sonnet with extended thinking) — 
  the strongest general reasoning models handle the complex synthesis 
  demands of GoT most reliably.
- Gemini Ultra/2.x Pro — strong for large-scale synthesis tasks, 
  particularly when combined with its large context window to hold 
  many interconnected "thought nodes" simultaneously.
- DeepSeek-R1 (for technical/mathematical GoT tasks) — capable of 
  complex multi-source reasoning synthesis in coding/math domains.
- NOTE: Like true Tree-of-Thoughts, RIGOROUS Graph-of-Thoughts (as 
  described in academic research) typically requires PROGRAMMATIC 
  orchestration — a system that manages the graph structure, tracks 
  which thoughts connect to which, and calls the model repeatedly to 
  generate/merge/refine nodes. A SIMPLIFIED single-prompt version 
  (below) captures much of the practical benefit for most real-world 
  use cases without needing custom orchestration code.
- Reserve this technique for the most capable/largest models — 
  smaller models (7B-13B) generally cannot reliably manage the 
  complexity of tracking and synthesizing multiple interconnected 
  reasoning threads.

-----------------------------
5. PROMPT FORMULA
-----------------------------
    [COMPLEX PROBLEM] + "Generate [N] independent thought nodes/
    approaches" + "Identify which nodes could be MERGED or 
    COMBINED" + "Synthesize a solution using insights from multiple 
    nodes" + "Refine by looping back to improve earlier ideas"

-----------------------------
6. PROMPT STRUCTURE (Simplified, Single-Prompt Version)
-----------------------------
    1. Problem Statement — the complex, multi-faceted problem.
    2. Node Generation — generate several independent "thought 
       nodes" (ideas, approaches, perspectives), each labeled 
       clearly (Node A, Node B, Node C...).
    3. Cross-Node Analysis — explicitly analyze which nodes have 
       complementary strengths that could be combined, and which 
       have conflicting weaknesses.
    4. Synthesis — construct a new, combined solution that draws 
       specific elements from multiple nodes.
    5. Refinement Loop — revisit and improve the synthesized 
       solution, potentially pulling in additional insight from a 
       node that wasn't initially used.
    6. Final Convergence — state the final, synthesized solution.

Example skeleton:
    "Problem: [COMPLEX PROBLEM]. 
    Step 1: Generate [Node A], [Node B], [Node C] — three distinct 
    approaches/perspectives. 
    Step 2: Analyze: what are the key strengths and weaknesses of 
    each node? Which nodes have complementary strengths? 
    Step 3: Synthesize a NEW solution that combines the best elements 
    of [relevant nodes] — explicitly state which element comes from 
    which node. 
    Step 4: Refine this synthesis — is there anything from the 
    remaining node(s) that could further improve it? 
    Step 5: State your Final Synthesized Answer."

-----------------------------
7. BEST PRACTICES
-----------------------------
- Clearly LABEL each thought node (Node A, Node B, etc.) so you and 
  the model can explicitly reference which ideas are being combined 
  at the synthesis step.
- Explicitly ask the model to identify COMPLEMENTARY vs. CONFLICTING 
  elements between nodes before attempting synthesis — this 
  structures the merging process rather than leaving it vague.
- Require the synthesis step to EXPLICITLY STATE which specific 
  element came from which node (e.g., "We take Node A's cost-
  efficiency and combine it with Node C's security approach") rather 
  than a vague blended summary.
- Include an explicit REFINEMENT step — after initial synthesis, ask 
  "can this be improved further using anything from the unused 
  node(s)?" to capture the "looping back" characteristic of true 
  graph-based reasoning.
- Reserve this technique for problems that genuinely benefit from 
  synthesis — verify first that the problem isn't better served by 
  simpler CoT or ToT.
- For very high-stakes or complex applications, consider breaking 
  this into multiple separate prompts/conversation turns (generate 
  nodes → analyze → synthesize → refine) rather than one giant 
  prompt, for clearer and more thorough reasoning at each stage.

-----------------------------
8. COMMON MISTAKES
-----------------------------
- MISTAKE: Using Graph-of-Thoughts for problems simple enough that 
  Tree-of-Thoughts or even basic Chain-of-Thought would suffice, 
  wasting significant tokens/effort.
  FIX: Reserve GoT for genuinely complex, multi-faceted problems 
  where synthesis across approaches is likely to produce a 
  meaningfully better result.

- MISTAKE: Generating multiple nodes but never truly synthesizing 
  them — just picking one node as the "winner" (this is actually just 
  ToT, not GoT).
  FIX: Explicitly require the synthesis step to draw specific, named 
  elements from multiple different nodes.

- MISTAKE: Vague synthesis that doesn't specify WHICH parts came from 
  WHICH nodes, making it unclear if genuine combination occurred or 
  if the model just wrote a generic summary.
  FIX: Require explicit attribution in the synthesis step ("this part 
  comes from Node B, this part comes from Node A").

- MISTAKE: Skipping the refinement/loop-back step, missing 
  opportunities to further improve the synthesized solution.
  FIX: Always include an explicit refinement step that revisits 
  unused nodes for additional improvement opportunities.

- MISTAKE: Attempting Graph-of-Thoughts with a model too small/weak 
  to reliably track multiple interconnected reasoning threads, 
  leading to confused or shallow synthesis.
  FIX: Reserve GoT for the most capable available models.

-----------------------------
9. EXAMPLES (BASIC, INTERMEDIATE, ADVANCED)
-----------------------------

--- BASIC EXAMPLE ---
Prompt:
"Problem: Design a study schedule for a student who needs to prepare 
for exams in 3 subjects (Math, Physics, Chemistry) over 2 weeks. 

Step 1: Generate Node A (a schedule prioritizing the weakest subject 
first), Node B (a schedule with equal daily time for all subjects), 
and Node C (a schedule using spaced repetition principles). 

Step 2: What are the strengths/weaknesses of each? 

Step 3: Synthesize a combined schedule that takes the best elements 
of multiple nodes, explicitly stating which element comes from which 
node. 

Step 4: State your Final Synthesized Schedule."

Expected Output:
Three distinct schedule nodes with brief strength/weakness analysis 
(e.g., Node A risks neglecting stronger subjects, Node B may 
under-serve the weakest subject, Node C has strong retention 
principles but needs a prioritization scheme), followed by a 
synthesized final schedule that explicitly combines, for example, 
Node A's weak-subject prioritization with Node C's spaced-repetition 
timing structure, clearly attributed.

--- INTERMEDIATE EXAMPLE ---
Prompt:
"Problem: I'm designing the memory architecture for a multi-agent AI 
system and need to decide how agents should share information with 
each other. 

Step 1: Generate Node A (a centralized shared memory/blackboard 
approach), Node B (a fully decentralized peer-to-peer memory-sharing 
approach), and Node C (a hierarchical approach where a 'coordinator' 
agent manages memory routing). 

Step 2: Analyze the strengths and weaknesses of each — consider 
scalability, consistency, latency, and complexity. 

Step 3: Synthesize a hybrid solution that combines complementary 
strengths from at least two nodes, explicitly stating which specific 
element comes from which node. 

Step 4: Refine — is there anything useful from the remaining node 
that could further improve this synthesis? 

Step 5: State your Final Synthesized Architecture."

Expected Output:
A structured analysis of the three approaches (e.g., Node A offers 
consistency but risks becoming a bottleneck; Node B offers 
scalability but risks inconsistency; Node C offers organized routing 
but adds a single point of coordination overhead), followed by a 
synthesis such as combining Node C's coordinator-based routing with 
Node A's centralized consistency guarantees for critical shared 
state, while using Node B's decentralized approach for less-critical, 
high-frequency local agent-to-agent updates — with a refinement step 
considering whether a caching mechanism from Node B could further 
reduce load on the Node C coordinator.

--- ADVANCED EXAMPLE ---
Prompt:
"Problem: I want to design the ideal content strategy for growing an 
AI/ML developer-focused audience, drawing on my background as a 
self-taught developer with deep hands-on project experience 
(multi-agent systems, RAG pipelines, cryptographic tools, CLI 
frameworks). 

Step 1: Generate Node A (a strategy focused on in-depth technical 
tutorials), Node B (a strategy focused on 'build in public' project 
documentation/storytelling), Node C (a strategy focused on creating 
comprehensive reference/educational resources like guides and 
libraries), and Node D (a strategy focused on original creative/
philosophical content reflecting personal voice and perspective). 

Step 2: Analyze the strengths, weaknesses, and audience-fit of each 
node given the stated background. 

Step 3: Synthesize a combined content strategy that draws specific, 
named elements from at least THREE of the four nodes, explicitly 
attributing each element. 

Step 4: Refine the synthesis by asking: does incorporating anything 
from the unused node add further value, or would it dilute focus? 
Justify your decision either way. 

Step 5: State your Final Synthesized Content Strategy."

Expected Output:
Four distinct strategic nodes with honest strength/weakness analysis 
tied to the stated background (e.g., Node A leverages deep technical 
expertise but is common/saturated content type; Node B is highly 
differentiating given genuine large-scale project work but requires 
more personal exposure; Node C leverages demonstrated strength in 
building comprehensive libraries/guides and is currently under-
saturated; Node D adds unique differentiation via personal 
philosophy/voice but risks narrower appeal), followed by a genuine 
synthesis combining, for example, Node C's comprehensive-resource 
strength as the core content pillar, Node B's build-in-public 
framing to add authentic narrative appeal, and Node A's technical 
depth applied selectively to flagship projects rather than generic 
tutorials — with a refinement step reasoning through whether Node D's 
philosophical/creative element should be woven in as occasional 
differentiating content or kept as a separate personal outlet, 
justified either way, culminating in a clearly stated Final 
Synthesized Content Strategy.

-----------------------------
10. REUSABLE PROMPT TEMPLATE
-----------------------------
    Problem: [YOUR COMPLEX, MULTI-FACETED PROBLEM]
    
    Step 1: Generate Node A, Node B, Node C [and more if needed] — 
    distinct approaches or perspectives on this problem.
    
    Step 2: Analyze the strengths and weaknesses of each node, and 
    identify which nodes have complementary strengths.
    
    Step 3: Synthesize a NEW combined solution drawing specific, 
    explicitly-attributed elements from at least two nodes (state 
    clearly: "this element comes from Node X").
    
    Step 4: Refine — could anything from the remaining, unused 
    node(s) further improve this synthesis? Justify your decision.
    
    Step 5: State your Final Synthesized Answer.
