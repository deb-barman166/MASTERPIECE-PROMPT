2. PURPOSE
────────────────────────────────────────────────────────────────────────────
This is the CAPSTONE TEMPLATE of the library — a single orchestration
document that sequences all 19 prior templates into one coherent, end-to-
end production pipeline for generating a complete horror short film or
feature treatment from a single starting concept. It does not replace any
individual template; it is the map showing exactly which template to run
when, what output feeds into what input, and how to maintain consistency
across the entire pipeline from first concept to final assembled cut.
Use this template first, as your production roadmap, before diving into
any individual template in the library.

5. INPUT STRUCTURE — THE FULL PRODUCTION PIPELINE
────────────────────────────────────────────────────────────────────────────
PROJECT SCOPE: {PROJECT_SCOPE}
STARTING CONCEPT: {STARTING_CONCEPT}
PRODUCTION TIMELINE: {PRODUCTION_TIMELINE}
TARGET PLATFORMS: {TARGET_PLATFORMS}

Execute the following pipeline in sequence. Each phase's output becomes a
locked input for all subsequent phases. Do not skip phases even under time
pressure — downstream templates depend on upstream consistency tokens
existing and being correct.

PHASE 1 — FOUNDATION (Narrative Architecture)
→ Run Template 01 (Horror Story Generator) using STARTING_CONCEPT as seed
→ Output: Full story with locked THEMATIC_SPINE, ANTAGONIST_LOGIC,
  ESCALATION_BEATS
→ CHECKPOINT: Confirm the core fear mechanic is singular and specific
  before proceeding

PHASE 2 — SCRIPT DEVELOPMENT
→ Run Template 02 (Horror Screenplay Generator) using Phase 1 output as
  SOURCE_MATERIAL
→ Output: Formatted screenplay with scene breakdown table (beat types,
  subtext layers)
→ CHECKPOINT: Confirm pacing profile is consistent and scene count matches
  PROJECT_SCOPE's runtime target

PHASE 3 — VISUAL DESIGN BIBLE (run in parallel, cross-reference each other)
→ Run Template 03 (Character Design) for every named character
→ Run Template 04 (Monster & Creature Design) for every non-human entity
→ Run Template 05 (Haunted Location Generator) for every distinct setting
→ Run Template 08 (Cinematography) once, project-wide
→ Run Template 09 (Lighting & Shadows) per location/scene-type
→ Run Template 10 (Atmosphere & Environment) per location/time-period
→ Output: Complete set of CONSISTENCY LOCK TOKENS for every character,
  creature, location, and the overall visual style
→ CHECKPOINT: Verify no two characters/creatures share confusable lock
  tokens; verify SIGNATURE_COLOR (Template 08) and antagonist camera motif
  (Template 07) are formally reserved and documented

PHASE 4 — SCENE ASSEMBLY (iterative, one pass per scene)
→ For each scripted scene, run Template 06 (Horror Scene Generator),
  pulling locked tokens from Phase 3
→ Run Template 07 (Camera Master) for each scene's specific shot
  requirements
→ Run Template 11 (Fear, Emotion & Acting) for each scene's performance
  beats
→ Run Template 12 (Horror Dialogue Generator) for each scene's dialogue,
  if any
→ Run Template 14 (VFX & Practical Effects) and Template 15 (Blood, Fog,
  Smoke & Weather) for any scene requiring elemental/practical effects
→ Output: Fully composed, generation-ready scene prompts for the entire
  script
→ CHECKPOINT: Run Template 19 (Quality & Consistency Checker) against a
  sample of completed scenes before proceeding to full-scale generation

PHASE 5 — AUDIO DESIGN
→ Run Template 13 (Sound Design & Music) for every scene, using the
  tension curves established in Phase 2/4
→ Output: Complete time-synced audio cue sheets for the full project
→ CHECKPOINT: Verify MOTIF_TOKEN usage discipline across the full project
  (Template 19's Motif Discipline Check)

PHASE 6 — GENERATION
→ Run Template 17 (Video Generation Master) to translate every composed
  scene into platform-specific generation prompts for TARGET_PLATFORMS
→ Run Template 18 (Negative Prompt Master) alongside every generation call
  to protect against known failure modes
→ Output: Generated video/image clips for every scene
→ CHECKPOINT: Run Template 19 against generated output (not just prompts)
  to catch generation-specific drift that couldn't be predicted from
  prompts alone

PHASE 7 — ASSEMBLY
→ Run Template 16 (Editing & Transitions) to determine cut logic and
  sequence the generated clips
→ Output: Fully assembled sequence/cut
→ FINAL CHECKPOINT: Run Template 19's PRE_RELEASE_FINAL_AUDIT (Advanced
  Version) across the complete assembled project

────────────────────────────────────────────────────────────────────────────
7. PROFESSIONAL INSTRUCTIONS
────────────────────────────────────────────────────────────────────────────
- Never skip Phase 1 or attempt to shortcut directly to scene generation
  (Phase 4) — every downstream template's quality depends on the
  specificity established in the foundational story and design phases;
  skipping ahead produces generic, inconsistent output regardless of how
  well individual scene prompts are written.
- Treat the Master Consistency Document as the single source of truth for
  the entire production — when any template's output seems to conflict
  with another, the Master Consistency Document (not memory or assumption)
  should resolve the discrepancy.
- Scale checkpoint frequency to QUALITY_BAR and PRODUCTION_TIMELINE
  realistically — a quick concept demo doesn't need every checkpoint in
  the full pipeline, but a production-ready project should not skip any of
  them.
- Maintain phase order even when working iteratively — it's fine to revisit
  Phase 1 after starting Phase 4 if a story problem is discovered, but the
  correction should propagate forward through all dependent phases rather
  than being patched only at the point it was discovered.

────────────────────────────────────────────────────────────────────────────
8. BEST PRACTICES
────────────────────────────────────────────────────────────────────────────
- For solo creators or small teams, consider running Phase 3's parallel
  templates sequentially instead if managing multiple simultaneous design
  threads becomes overwhelming — the pipeline's logic holds either way, as
  long as all Phase 3 outputs are complete and cross-referenced before
  Phase 4 begins.
- Budget real time for the checkpoint stages — they are not optional
  overhead but the mechanism that prevents expensive downstream rework
  from compounding consistency errors across dozens of generated scenes.
- Keep the Master Consistency Document in a format everyone on the team
  (or future-you, returning to the project later) can quickly reference
  without re-reading every prior template output in full.
- When production timeline is very short, prioritize rigor in Phases 1-3
  over Phases 4-7 — a slightly less polished generation of a well-designed
  scene outperforms a highly polished generation of an inconsistent one.

────────────────────────────────────────────────────────────────────────────
9. HORROR CINEMATIC TECHNIQUES
────────────────────────────────────────────────────────────────────────────
This template's own "technique" is STRUCTURAL DISCIPLINE — the recognition
that Hollywood-quality horror (in any medium) comes from a coherent system
of reinforcing choices (a consistent antagonist logic, a disciplined
signature motif, a restrained performance style) rather than from any
single clever trick. The specific techniques catalogued across Templates
01-19 only compound into genuine cinematic quality when applied through
this kind of consistent, cross-referenced pipeline rather than in
isolation. Revisit each template's "Horror Cinematic Techniques" section
during the relevant pipeline phase rather than trying to apply all
techniques everywhere at once — over-stuffing every scene with every
technique from every template dilutes rather than strengthens the result.

────────────────────────────────────────────────────────────────────────────
10. CAMERA & LIGHTING GUIDE
────────────────────────────────────────────────────────────────────────────
Established once in Phase 3 (Templates 07/08/09) and referenced, never
re-derived, throughout Phases 4-7. The single most common cause of visual
inconsistency in AI-assisted horror production is treating camera and
lighting decisions as scene-by-scene creative choices rather than project-
wide systems established early and applied consistently — this pipeline
structure exists specifically to prevent that failure mode.

────────────────────────────────────────────────────────────────────────────
11. SOUND & ATMOSPHERE GUIDE
────────────────────────────────────────────────────────────────────────────
Established in Phase 5 but DESIGNED conceptually as early as Phase 1
(Template 01's sound motif and silence notes) — sound should never be an
afterthought bolted onto finished visuals. This pipeline deliberately
plants audio identity (the antagonist's motif, key silence cues) in the
foundational story phase precisely so Phase 5's full audio design has a
consistent conceptual seed to build from, rather than inventing sound
identity from scratch after all visual decisions are already locked.
